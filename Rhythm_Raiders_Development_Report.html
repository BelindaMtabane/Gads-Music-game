1. Project Overview

Rhythm Raiders is a 3D forward-scrolling chase/collection runner built in Unity 6 (URP 17.x, C#). The player sprints down a themed track, collects two musical artifacts to win, dodges obstacles, and outruns a security guard across three distinct levels.

4. Feedback Not Implemented — Reasons

Not every suggestion was actioned. Below is a transparent record of what was deferred or rejected, and the professional rationale behind each decision.

Feedback ItemDecisionReason
Side seating / environment art (P2) Deferred Valid set-dressing for the venue fantasy but requires custom 3D modelling. High time cost vs. low impact on the core loop before the submission deadline. Documented for a future art pass.
Full cinematic curtain cut-scenes (P1) Deferred P1 wanted stronger transition cinematics. We added themed end walls for L2 and L3 as a faster gain. Full animated curtain transitions require additional art and animation time.
Live AI dialogue in-game Rejected Real-time LLM calls during gameplay introduce unacceptable latency, require persistent internet, and risk demo instability. Scripted narration written with AI-assisted drafting offline keeps the experience stable and dialogue quality controlled.
Multiplayer Rejected Entirely out of Part 3 scope. Networking would require a full rebuild of the core game loop.
Rhythm-timing mechanic Deferred Beat-synced gameplay conflicts with the current runner scope and would need a full audio-gameplay integration system. Noted as a compelling direction for a future version.
Much longer level (P4) Partial Extended RunLengthController and increased spawn density. A complete level redesign with new obstacles and biomes is staged for a future sprint, not this submission window.
5. Extra Work Done — Beyond Playtest Feedback

Several substantial improvements were made that were not directly requested by playtesters but significantly improve robustness, architecture, and visual identity.

5.1 Three-Level Architecture & Scene Renames

The game was restructured from a single scene into a proper three-level progression. Scenes were renamed to reflect their themes (MainGameL1Opera, Level2Museum, Level3UndergroundDance). A central GameplaySceneNames.cs constants file was introduced as the single source of truth — eliminating hardcoded strings scattered across 15+ scripts and editor tools.

5.2 Sci-Fi HUD System

A complete HUD replacement was designed using the AIRIDev Sci-fi UI Icons pack. The new HUD features icon-led rows for Vibe, Shield, Artifacts, Guard distance, Speed Boost, Score, and Level. A HUDScaler component allows Inspector-controlled resizing. A dedicated editor tool (Tools → Setup Gameplay HUD) applies the full HUD to any scene in one click.

5.3 Dual Health System (Shield + Vibe)

Beyond renaming "Hits Left", the health system was architecturally expanded. All obstacles now drain Vibe directly (default 5 per hit) in addition to draining Shield. Shield absorbs damage first; when depleted, damage spills into Vibe. This creates meaningful tension between two health meters.

5.4 Per-Level Set Dressing & Atmospheric End Walls

Each level has unique visual decoration built at runtime by LevelSetDressing.cs: opera house curtain pillars (L1), museum display cases (L2), neon club strips (L3). Each level also has a distinctive end wall placed far ahead — a marble museum gate (L2) and a neon portal (L3) — giving visual depth to the track without blocking player movement (no physics colliders).

5.5 Pause Menu (Full Feature)

A complete pause menu was built with Resume, Settings (live music + SFX volume sliders), and Main Menu buttons. The root bug preventing buttons from working was diagnosed and fixed: PlayerMovement.Update() was re-locking the cursor every frame including while paused at timeScale=0. Fixed with a single timeScale guard (if (Time.timeScale > 0f)).

5.6 Architecture & Editor Tooling

Fourteen editor tools were updated or created under the Tools menu to allow one-click setup of any scene: HUD, pause screen, narration, audio, build settings, character physics, and more. This ensures the game can be rebuilt from source without manual Inspector wiring — critical for a project using AI-assisted development where setups must be reproducible.

8. Closing Notes

Rhythm Raiders has been transformed from a single-scene AI-assisted prototype into a three-level polished runner that a stranger can pick up and play without guidance. The Goethe-Institut playtesting session was the central event that prioritised the refinement work — player voices confirmed what to fix (UI, visibility, pacing) and what to protect (the core concept, AI-assisted narration, the music-gaming vibe).

Work that went beyond the feedback — the three-level architecture, dual health system, sci-fi HUD, level set dressing, and full pause menu — reflects professional practice: a game should not just address critique but also build the systems that make future iteration possible.

All source changes are committed to the harriet's_work branch on BelindaMtabane/Gads-Music-game and documented in refinements-changes.md.
